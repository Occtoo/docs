---
title: "Add or edit a property"
description: "Define a source property, or change the type, capabilities and interface settings of an existing one."
---

**Add property** and the pencil on a row both open the same form. Add mode is titled **Add property** with an **Add** button; edit mode is **Edit property** with **Save**.

## Add a property

<Steps>
  <Step title="Press Add property">

    In the **Properties** widget on the source page.

  </Step>
  <Step title="Fill in the basic fields">

    ![The Add property dialog](/images/guides/studio/sources/add-property-dialog.png)

    - **ID** — required, 2 to 50 characters, letters, digits, hyphens and underscores only. It has to start with a lowercase letter, and `id` is reserved. It has to be unique in the source; a clash gives "A property with this ID already exists".
    - **Display name** — required, 2 to 50 characters. The name shown in Studio.
    - **Preferred card property ID** — optional, up to 50 characters. A casing-only override for the identifier suggested when this property is added to a card.
    - **Data type** — required, defaults to **Text**.
    - **Delimiter** — appears for **List** and **Localized list**, and is required there. Choose comma, semicolon, pipe, slash or colon.
    - **Description** — optional free text, shown under the ID in the property table.

    <Info>
    Studio lowercases the ID it sends, so `colorCode` is stored as `colorcode`. Use **Display name** for the casing you want to read in Studio.
    </Info>

  </Step>
  <Step title="Set capabilities">

    Choose whether the property can be searched, filtered and converted. See [Property capabilities](/guides/studio/sources/property-capabilities).

  </Step>
  <Step title="Set the interface settings">

    ![Interface settings](/images/guides/studio/sources/property-interface-settings.png)

    - **Display section** — **Choose an existing section** picks one of the source's sections (or **General**); **Create a new section** lets you type a new name, up to 50 characters.
    - **Show on interface** — **Yes** gives the property a column in the entries table and a row in the entry panel. Its info icon notes that "The entries table shows columns for the first 6 shown properties only".
    - **Editable** — **Yes** lets the value be changed by hand on an entry. **No** makes it read-only in Studio, so it can only change through onboarding.

  </Step>
  <Step title="Press Add">

    **Add** stays disabled until you change something. Occtoo confirms with "Property &lt;display name&gt; added".

  </Step>
</Steps>

<Info>
Changing the display section is a second save behind the scenes, because sections live on the source rather than on the property. If the property saves but the section does not, the toast reports the section error and the property change is already in place.
</Info>

## Edit a property

![The Edit property dialog](/images/guides/studio/sources/edit-property-dialog.png)

**ID** and **Display name** are read-only in edit mode. Everything else can be changed: preferred card property ID, data type, delimiter, description, capabilities and interface settings.

<Warning>
Changing the data type of a property that already holds data changes how existing values are read. Check what the source is sending before switching type, especially between **Text** and the list types, where the delimiter decides how a value splits.
</Warning>

The property goes to **Updating** while the change is applied, and cannot be edited again until it is **Active**.

## Preferred card property ID

This field only changes casing. The value has to match the property ID letter for letter apart from case, otherwise you get "The preferred card property ID may only change the casing of the source property ID."

Its help text has two forms. When the source suggests an identifier it reads "Leave empty to use the suggested baseColors identifier.", with that suggestion as the field's placeholder. When there is no suggestion it reads "Optional casing-only override used when adding this property to a card."

## Delimiters

**List** and **Localized list** need a delimiter, because a list arrives as one string that Occtoo splits. The options are:

| Option | Character |
| --- | --- |
| Comma | `,` |
| Semicolon | `;` |
| Pipe | `\|` |
| Slash | `/` |
| Colon | `:` |

Switch a list property to a non-list type and the delimiter clears itself.
