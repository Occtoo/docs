---
title: "Destination"
---

Building new and fast digital experiences requires data to be available anywhere around the world within milliseconds, pushed to various platforms in the correct format and fashion. This is the task of the Occtoo Destination block. Occtoo can scale any data around the world when needed, giving developers access to data as though it were local to their applications. The data is geographically scaled, with millisecond response times, fully documented (using Swagger), and ready for front-end developers to start using right away.

## Endpoints

Destinations are where the experience data sets are exposed as real-time APIs. These API endpoints are fully customizable regarding both their content, via application of specified segments, and their structure, using the platform's configuration options to specify what properties and relations to expose. Each published destination comes with its own built-in documentation, which further aids in understanding how to consume the data.

## Security

Destinations are either *protected* or *unprotected*. Protected destinations require that an application is registered, and clients can only query endpoints by providing a previously generated secret (API token) for each request.

## Regions

Regions are the geographic locations where the destination is hosted. A destination is assigned to one or more regions, with one region specified as the default. The available regions depend on the tenant's setup.

## Languages

Destinations can provide data in one or multiple languages, and the languages of the target destination are matched with the languages uploaded via the [source](/concepts/source).
