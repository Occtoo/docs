The Occtoo Events API lets you react to changes across your tenant — sources, cards, segments, destinations, endpoints, users, and managed tags — without polling each resource. Every change is published as a [CloudEvents](https://cloudevents.io/) message (`application/cloudevents+json`).

## Consume and inspect events

<Columns cols={2}>
  <Card title="Pull">
    Page through events with `GET /v1/events` using a cursor. Good for batch processing and catch-up jobs.
  </Card>
  <Card title="Metadata">
    Inspect the first and latest retained positions and exact event count with `GET /v1/events/metadata`. Good for consumer health checks.
  </Card>
  <Card title="Stream" href="/api-reference/events/streaming">
    Subscribe to a live, ordered Server-Sent Events stream at `GET /v1/events/stream`. Good for real-time reactions.
  </Card>
  <Card title="Durable consumer" href="/api-reference/events/durable-consumers">
    Pull leased batches from a server-tracked position and acknowledge them. Good for competing workers that should not store their own cursor.
  </Card>
</Columns>

<Note>
Occtoo can also push these events to you. Create a webhook, Azure Storage Queue or Azure Service Bus subscription in Studio — see [Find event subscriptions](/guides/studio/events/find-subscriptions).
</Note>

## Filter by subject

Use the `filter` query parameter to select events about one entry or resource. The same expression works with pull (`GET /v1/events`), metadata (`GET /v1/events/metadata`), and SSE (`GET /v1/events/stream`).

```bash
curl --get 'https://api.occtoo.com/v1/events' \
  --header 'Authorization: Bearer <access-token>' \
  --data-urlencode 'filter=type eq "source_entry.updated" and sourceId eq "products" and subject eq "sku-123"'
```

`subject` is a CloudEvent envelope field. Compare its complete value as an exact, case-sensitive string. Do not split it on `/` or `.`: those characters can be part of an ID. Partial and wildcard matches are not supported.

Its meaning depends on the event type:

| Event family | `subject` identifies |
| --- | --- |
| `source.*` | The source (`sourceId`). |
| `source_entry.*` | The entry within its source (`entryKey`). |
| `card_definition.*` | The card definition (`cardDefinitionId`). |
| `card.*` | The card (`cardId`). |
| `segment.*` | The segment (`segmentId`). |
| `destination.*` | The destination, or its API-version ID when a destination ID was not supplied. |
| `destination_entry.*` | The destination entry (`entryId`). |
| `endpoint.*` | The endpoint (`endpointId`). |
| `user.*` | The user (`userId`). |
| `managed_tag_list.*` | The managed tag list (`managedTagId`). |
| `managed_tag_value.*` | The value within its list (`key`). |

Combine `subject` with the event type and parent identifiers to distinguish entries that share an ID:

```text Card
type eq "card.updated" and cardDefinitionId eq "products" and subject eq "card-123"
```

```text Destination entry
type eq "destination_entry.updated" and destinationId eq "catalog" and apiVersion eq "3" and endpoint eq "products" and subject eq "entry-123"
```

The field names `entryKey`, `cardId`, and `entryId` are not separate filter operands. Use `subject` for these values. Check `GET /v1/event-types` for the properties supported by each type.

<Note>
  Only events processed after subject filtering was enabled can match a subject condition. Older retained events are not backfilled, even when their payload contains `subject`. Filters without a subject condition continue to match older events. An `or` branch without a subject condition can also match them.
</Note>

You can combine comparisons with `and`, `or`, and parentheses. Filter values must be double-quoted strings of 1–200 characters. The existing limits remain 4,096 characters per expression, 50 comparisons, and eight nesting levels.

The same subject matching applies to webhook and queue subscription filters. Every branch of a subscription filter must also constrain `type`.

## Filter by endpoint safe name

For `destination_entry.updated` and `destination_entry.deleted`, use `endpoint` to match the endpoint's safe name, such as `products`. The public filter property is `endpoint`, not `endpointSafeName`. Matching is exact and case-sensitive.

Combine it with `destinationId` to scope the safe name to one destination:

```text
(type eq "destination_entry.updated" or type eq "destination_entry.deleted") and destinationId eq "<destination-id>" and endpoint eq "products"
```

This filter can match the same endpoint safe name across destination API versions. Add `apiVersion` or `apiVersionId` only when you want to restrict it to one version. Use `endpointId` when you want to match a specific endpoint identifier instead.

`endpoint.created`, `endpoint.updated`, and `endpoint.deleted` support `endpointId`, but do not support the `endpoint` safe-name filter.

To match several safe names, group them with `or`:

```text
type eq "destination_entry.updated" and destinationId eq "<destination-id>" and (endpoint eq "products" or endpoint eq "categories")
```

The same expressions work for pull, metadata, live streams, and webhook or queue subscriptions.

<Note>
  Making a property filterable applies only to events processed after support for that property is enabled. Older events are not backfilled. For example, an older event cannot match an `endpoint` condition even if its payload already contains `endpoint`. Filters without that condition, including an `or` branch without it, can still match older events.
</Note>

## Inspect stream metadata

Call `GET /v1/events/metadata` to inspect the retained stream without retrieving event payloads. It accepts the same optional `filter` as the pull and stream endpoints.

```bash
curl --get 'https://api.occtoo.com/v1/events/metadata' \
  --header 'Authorization: Bearer <access-token>' \
  --data-urlencode 'filter=type eq "source.updated" and sourceId eq "products"'
```

```json
{
  "first": {
    "sequence": "003.00000000000000184001",
    "time": "2026-07-04T08:10:00Z"
  },
  "latest": {
    "sequence": "003.00000000000000184467",
    "time": "2026-07-04T09:15:12.345Z"
  },
  "after": "<opaque pull cursor>",
  "total": 184
}
```

- `first` and `latest` identify the boundaries of the retained filtered view. Their `time` is `null` when the CloudEvent has no time.
- `after` is an opaque pull cursor for the `latest` position. Store it as a checkpoint or pass it to `GET /v1/events`.
- `total` is the exact count across the complete retained filtered view, not the count after a consumer checkpoint.

Compare `latest.sequence` with your last successfully processed sequence to determine whether a consumer is caught up. Do not use the difference between sequences as a pending-event count because filtered-out events can create gaps.

When no retained event matches, `first`, `latest`, and `after` are `null`, and `total` is `0`.

## Event types

Occtoo publishes 36 event types across sources, cards, segments, destinations, endpoints, users, and managed tags. All are currently at payload schema version `1.0`.

Every `data` payload includes these two properties, so they are omitted from the tables below:

| Property | Type | Description |
|---|---|---|
| `correlationIds` | `string[]` | Ids correlating this event with the operation that caused it. Always present. |
| `actor` | `object \| null` | Who caused the change, as `{ "id": "<user or service id>" }`. `null` for system-initiated changes. |

In the tables, `?` marks a property that is not required — it may be absent or `null`. See the [data property reference](#data-property-reference) for types and meanings.

### Sources

| Event type | Description | Data properties |
|---|---|---|
| `source.created` | A source was created. | `sourceId` |
| `source.updated` | A source configuration changed. | `sourceId`, `changes`, `properties?` |
| `source.deleted` | A source was deleted. | `sourceId` |
| `source_entry.added` | A source entry was added. | `sourceId`, `entryKey`, `version`, `properties?` |
| `source_entry.updated` | A source entry changed. | `sourceId`, `entryKey`, `version`, `changedProperties`, `valuesTruncated`, `values?` |
| `source_entry.deleted` | A source entry was deleted. | `sourceId`, `entryKey`, `version` |

### Cards

| Event type | Description | Data properties |
|---|---|---|
| `card.updated` | A card changed as a result of source data. | `cardDefinitionId`, `cardId`, `changedProperties` |
| `card.segment_membership_changed` | A card entered or left a segment. | `cardDefinitionId`, `cardId`, `segmentId`, `change` |
| `card_definition.created` | A card definition was created. | `cardDefinitionId` |
| `card_definition.updated` | A card definition changed. | `cardDefinitionId`, `changes` |
| `card_definition.activated` | A card definition became active. | `cardDefinitionId` |
| `card_definition.deleted` | A card definition was deleted. | `cardDefinitionId` |
| `card_definition.restored` | A card definition was restored. | `cardDefinitionId` |

### Segments

| Event type | Description | Data properties |
|---|---|---|
| `segment.created` | A segment was created. | `segmentId`, `segmentDefinitionId`, `cardDefinitionId?` |
| `segment.updated` | A segment changed. | `segmentId`, `segmentDefinitionId`, `changes`, `cardDefinitionId?` |
| `segment.archived` | A segment was archived. | `segmentId`, `segmentDefinitionId`, `cardDefinitionId?` |
| `segment.restored` | A segment was restored. | `segmentId`, `segmentDefinitionId`, `cardDefinitionId?` |
| `segment.deleted` | A segment was deleted. | `segmentId`, `segmentDefinitionId`, `cardDefinitionId?` |

### Destinations

| Event type | Description | Data properties |
|---|---|---|
| `destination.created` | A destination was created. | `destinationId` |
| `destination.published` | A destination was published. | `destinationId` |
| `destination.stopped` | A destination was stopped. | `destinationId` |
| `destination.deleted` | A destination was deleted. | `destinationId` |
| `destination_entry.updated` | An entry was written to a destination endpoint. | `destinationId`, `apiVersionId`, `apiVersion`, `endpointId`, `endpoint`, `entryId`, `version`, `changedProperties`, `valuesTruncated`, `values?` |
| `destination_entry.deleted` | An entry was removed from a destination endpoint. | `destinationId`, `apiVersionId`, `apiVersion`, `endpointId`, `endpoint`, `entryId`, `version` |

### Endpoints

| Event type | Description | Data properties |
|---|---|---|
| `endpoint.created` | A destination endpoint was created. | `destinationId`, `apiVersionId`, `apiVersion`, `endpointId` |
| `endpoint.updated` | A destination endpoint changed. | `destinationId`, `apiVersionId`, `apiVersion`, `endpointId` |
| `endpoint.deleted` | A destination endpoint was deleted. | `destinationId`, `apiVersionId`, `apiVersion`, `endpointId` |

### Users

| Event type | Description | Data properties |
|---|---|---|
| `user.created` | A tenant user was created. | `userId`, `email?`, `firstName?`, `lastName?` |
| `user.updated` | A tenant user changed. | `userId`, `email?`, `firstName?`, `lastName?` |
| `user.deleted` | A tenant user was deleted. | `userId`, `email?`, `firstName?`, `lastName?` |

### Managed tags

Managed tag events are available through the Events API, SSE, durable consumers, webhooks, Azure Storage Queue, and Azure Service Bus.

| Event type | Description | Data properties |
| --- | --- | --- |
| `managed_tag_list.created` | A list was created. | `managedTagId`, `displayName`, `type`, `createdAt`, `lastModifiedAt`, `parentId?`, `createdBy?`, `updatedBy?` |
| `managed_tag_list.updated` | List metadata changed, including its parent. | `managedTagId`, `displayName`, `type`, `createdAt`, `lastModifiedAt`, `parentId?`, `createdBy?`, `updatedBy?` |
| `managed_tag_list.deleted` | A list and its values were deleted. | `managedTagId` |
| `managed_tag_value.added` | A value was added. | `managedTagId`, `key`, `value?`, `order`, `createdAt`, `createdBy`, `valueTruncated`, `parentKey?`, `lastModifiedAt?`, `updatedBy?` |
| `managed_tag_value.updated` | A value's content, order, or parent key changed. | `managedTagId`, `key`, `value?`, `order`, `createdAt`, `createdBy`, `valueTruncated`, `parentKey?`, `lastModifiedAt?`, `updatedBy?` |
| `managed_tag_value.deleted` | A value was deleted directly. | `managedTagId`, `key` |

List creation and update events contain metadata, never the list's values. Value addition and update events contain replacement snapshots: `value` is a string for a `Text` list or a language-to-string object for a `LocalizedText` list. Replace your stored translations with this object; a missing language means that translation was removed. An omitted `parentId` or `parentKey` means there is no parent.

For all six types, `source` is `/managed-tags/{managedTagId}`. The `subject` is the list UUID for list events and the opaque, case-sensitive value key for value events. Use `managedTagId` to filter by list and `subject` to filter by value key. The data field `key` is not a separate filter operand.

#### Value update example

```json
{
  "specversion": "1.0",
  "id": "76b466ae-1520-5bdf-b9a9-99360e92283f",
  "type": "managed_tag_value.updated",
  "source": "/managed-tags/42f3cce5-a2b8-4cf9-9c2e-8c07a2ced339",
  "subject": "blue",
  "time": "2026-11-05T09:15:12Z",
  "datacontenttype": "application/json",
  "dataschema": "https://api.occtoo.com/v1/events/schemas/managed_tag_value.updated/1.0",
  "sequence": "003.00000000000000184467",
  "tenantid": "6dc156d9-e25d-470a-bbba-7b503e5b4769",
  "data": {
    "managedTagId": "42f3cce5-a2b8-4cf9-9c2e-8c07a2ced339",
    "key": "blue",
    "value": { "en": "Blue", "sv": "Blå" },
    "order": 2,
    "createdAt": "2026-11-01T08:00:00Z",
    "createdBy": "c157d71e-b930-4eae-9c3d-23a8de1a1cbc",
    "lastModifiedAt": "2026-11-05T09:15:12Z",
    "updatedBy": "c157d71e-b930-4eae-9c3d-23a8de1a1cbc",
    "valueTruncated": false,
    "correlationIds": [],
    "actor": { "id": "c157d71e-b930-4eae-9c3d-23a8de1a1cbc" }
  }
}
```

#### List changes and deletion

Handle list and value hierarchy changes as follows:

- Deleting a list emits one `managed_tag_list.deleted` event and a `managed_tag_list.updated` event for each child list detached from it. It does not emit individual value deletions.
- Changing a list's parent emits one `managed_tag_list.updated` event. Its values' parent keys are cleared without individual value update events.
- Deleting a parent value directly emits `managed_tag_value.deleted` and updates for surviving child values whose parent keys are cleared.

If you maintain a copy of values, subscribe to list events as well. Discard a deleted list's values and refetch values when a list's parent changes. Make processing idempotent and handle delayed value events without recreating a deleted list.

This filter receives all list and value changes for one list:

```text
(type eq "managed_tag_list.created" or type eq "managed_tag_list.updated" or type eq "managed_tag_list.deleted"
 or type eq "managed_tag_value.added" or type eq "managed_tag_value.updated" or type eq "managed_tag_value.deleted")
and managedTagId eq "42f3cce5-a2b8-4cf9-9c2e-8c07a2ced339"
```

Unchanged writes emit no events and do not advance modification timestamps. Batch writes emit one event per changed value. Only future changes are emitted; existing lists and values are not backfilled.

#### Large values

When the event exceeds the 60 KiB envelope budget, `value` is omitted and `valueTruncated` is `true`. Identity and metadata remain. Fetch the full value with `GET /v1/managed-tags/{managedTagId}/values/{key}` using a credential with `read:cards`. URL-encode the key.

The fetch returns current state, which may be newer than the event or already deleted. Do not clear your stored content when `valueTruncated` is `true`. See the [Configuration API reference](/api-reference/configuration/overview) for authentication and managed-tag reads.

## Data property reference

Properties marked **filterable** can be used in event subscription filters and the filter grammar of `GET /v1/events`, `GET /v1/events/metadata`, and `GET /v1/events/stream`. The exact set accepted for a given type is returned as `filterableProperties` by `GET /v1/event-types`. You can also filter by the envelope fields `type` and [`subject`](#filter-by-subject).

| Property | Type | Filterable | Description |
| --- | --- | --- | --- |
| `apiVersion` | `string` | Yes | Destination API version name the endpoint belongs to. |
| `apiVersionId` | `string` | Yes | Identifier of the destination API version. |
| `cardDefinitionId` | `string` | Yes | Identifier of the card definition. Nullable on `segment.*` events. |
| `cardId` | `string` | — | Identifier of the individual card. |
| `change` | `string` | — | The membership change that occurred on `card.segment_membership_changed`. |
| `changedProperties` | `string[]` | — | Names of the properties that changed. |
| `changes` | `string[]` | — | Names of the configuration areas that changed. |
| `destinationId` | `string` | Yes | Identifier of the destination. |
| `email` | `string \| null` | — | User email address. |
| `endpoint` | `string` | Yes | Safe name of the destination endpoint. Filterable on `destination_entry.updated` and `destination_entry.deleted` only. |
| `endpointId` | `string` | Yes | Identifier of the destination endpoint. |
| `entryId` | `string` | — | Identifier of the destination entry. |
| `entryKey` | `string` | — | Key of the source entry within its source. |
| `firstName` | `string \| null` | — | User first name. |
| `lastName` | `string \| null` | — | User last name. |
| `properties` | `array \| null` | — | On `source.updated`, the changed source properties as `{ "id", "change" }` objects. On `source_entry.added`, the entry's properties. |
| `segmentDefinitionId` | `string` | Yes | Identifier of the segment definition. |
| `segmentId` | `string` | Yes | Identifier of the segment. |
| `sourceId` | `string` | Yes | Identifier of the source. |
| `userId` | `string` | Yes | Identifier of the tenant user. |
| `managedTagId` | `string` | Yes | UUID of the managed tag list. Present on all list and value events. |
| `displayName` | `string` | No | Managed tag list's display name. |
| `type` (in `data`) | `string` | No | Managed tag list kind: `Text` or `LocalizedText`. The filter operand `type` refers to the CloudEvent event type instead. |
| `parentId` | `string` | No | Parent list UUID. Omitted when the list has no parent. |
| `key` | `string` | No | Value key within its managed tag list. Filter using the envelope `subject`. |
| `value` | `string or object` | No | Full text or language-to-string value. Omitted when `valueTruncated` is `true`. |
| `valueTruncated` | `boolean` | No | Whether managed tag value content was omitted because the event exceeded the size limit. |
| `order` | `number` | No | Managed tag value's sort order. |
| `parentKey` | `string` | No | Key of the parent value. Omitted when the value has no parent. |
| `createdAt` | `string` | No | Creation timestamp in date-time format. |
| `lastModifiedAt` | `string` | No | Modification timestamp in date-time format. Lists use `createdAt` until modified; values may omit this field until modified. |
| `createdBy` | `string` | No | Creator's ID. Required on value snapshots; optional on list snapshots. |
| `updatedBy` | `string` | No | Last updater's ID, when available. |
| `values` | `object \| null` | — | Changed values keyed by property name, each an array of `{ "value", "language?" }`. Omitted when `valuesTruncated` is `true`. |
| `valuesTruncated` | `boolean` | — | Whether `values` was dropped because the payload exceeded the size limit. |
| `version` | `string \| integer` | — | Monotonic version of the entry, as an integer-valued string or integer. |

<Note>
`GET /v1/event-types` is the authoritative, machine-readable version of this page — it returns each type's description, `filterableProperties` and full inline JSON Schema. Fetch a single schema with `GET /v1/events/schemas/{type}/{version}`.
</Note>

## Resuming a stream

The SSE `id` field of each streamed event contains a raw, resumable event sequence. Pass it (or a pull cursor) as the `after` query parameter when reconnecting to continue exactly where you left off — no events lost, none replayed.

<Note>
The Events API uses the same authentication as the rest of the platform API: a bearer token or API key. See the [API overview](/api-reference/overview#authentication) for how to obtain tokens.
</Note>
